How it works

Map → Prioritize → Probe → Prove → Report

Skills are model-invoked: Claude reads each short description and pulls in the full playbook only when your task matches. Every lead has to climb the eight-rung Trinet Validation Ladder before it counts as a finding.

  • Authorization gate — written scope first, or passive/advisory mode only.
  • Validation Ladder — real class · reachable · exploitable now · concrete impact · in scope · reproducible · not a duplicate · evidence captured.
  • Impact-first reports — HackerOne / Bugcrowd / Intigriti / Immunefi templates.

Automation, not just advice

The skills don't only describe the work — they run it

Bundled, scope-gated scripts execute from the Map phase, each skipping any tool you don't have and timing out rather than hanging.

  • recon.sh — subfinder → httpx → katana → gau → nuclei, structured run dir.
  • ghostjs-scan.sh — GhostJS JS-secret + npm dependency-confusion scan.
  • memory.sh — persistent hunt-memory so a resumed hunt builds on the last.
  • Subagents — recon-runner (ranked surface, off your context) and autopilot.
/recon/validate/report/chain/remember/pickup/autopilot/cloud-recon/llm-redteam/takeover/jwt-scan
Autopilot — the whole loop, safely. /autopilot <target> drives scope → recon → hunt → validate → report, but it's human-on-the-loop: it stops at mandatory checkpoints before any active testing, before state-changing exploitation, and before submitting — and hard-refuses out-of-scope hosts, DoS, credential spraying, and destructive actions.

Install

Two minutes, one correct path

The plugin brings the skills, slash commands, subagents, and scripts — and wires up the runtime they need. Prereqs: Claude Code + git.

Add the marketplace

/plugin marketplace add trinetlayer/claude-HunterSkills

Install the plugin

/plugin install trinetlayer-bug-hunting@trinetlayer

Restart Claude Code

Skills load at startup — start a fresh session.

Verify

Say “help me test this in-scope web app for IDOR” — Claude should load web-app-pentest and ask for scope. Type / to see the commands.

Skills only, no plugin runtime? Clone and run the installer — it auto-discovers every skill folder (slash commands and subagents need the plugin path above):
git clone https://github.com/trinetlayer/claude-HunterSkills.git
cd claude-HunterSkills
./install.sh # --link to auto-update · --project DIR for one engagement
Run Burp, Caido, HackerOne, or ProjectDiscovery tools? Wire them to Claude over MCP and the skills will use them — opt-in via mcp/mcp.json.example. The HackerOne server is read-only; submissions stay behind a human confirmation.
